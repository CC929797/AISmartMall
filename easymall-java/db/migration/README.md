# 数据库迁移记录

本目录在阶段 0 建立，用于保存后续经过验证的结构迁移。没有配置 Flyway / Liquibase 自动执行迁移，脚本需按对应验证记录单独执行。

步骤04新增 V20261103_01__expand_password_hash.sql，扩容现有密码列并调整为区分大小写的排序规则。已在隔离 easymall_test 验证；已有开发库需按[密码迁移记录](../../docs/verification/04-password-migration.md)单独执行，应用不会自动运行该脚本。

步骤11A新增 `V20261107_01__business_task.sql`，创建任务表、事件唯一键、到期/租约索引及状态约束，要求 MySQL 8.0.16+ / InnoDB。本轮仅在隔离 `127.0.0.1:13306/easymall_test` 的 MySQL 8.4.9 验证；未修改开发库。启用真实业务投递前，应先在目标库检查同名表不存在，再执行此单条 CREATE TABLE 并核对索引/约束。DDL 会隐式提交，不能通过业务事务回滚；应用回退时关闭新投递/Worker并保留任务表和数据，不自动删表。已有同名表时停止执行并人工核对，禁止通过清表后重建规避差异。详见[11A验证记录](../../docs/verification/11a-reliable-task.md)。

## 使用顺序

1. 使用只读账号，在明确选中的测试库运行 `../inspection/schema-baseline.sql`，记录实际字段、长度、索引和约束。
2. 对照当前实体、Mapper 和业务规则说明需要修改的原因。源码不能代替实际 DDL；未检查的约束标记为未知。
3. 为一项独立改动编写迁移，建议命名为 `VYYYYMMDD_NN__description.sql`。命名约定不代表已经有自动迁移器。
4. 记录适用的数据库版本、前置结构、兼容窗口、预计锁表影响，以及异常时的恢复办法。
5. 先在独立测试库执行并验证结构、旧数据兼容性和相关业务测试，再决定后续环境的执行方式。
6. 将实际执行命令、时间、脚本版本、结果及限制记录到对应的 `docs/verification/` 工作包，不把“脚本已写”视为“数据库已升级”。

## 每次迁移应附带的信息

| 项目 | 要求 |
|---|---|
| 目的 | 明确对应路线图步骤和业务不变量 |
| 前置条件 | 已核对的数据库版本、表结构及已有约束 |
| 数据影响 | 说明是否需要回填、分批处理或处理历史重复数据 |
| 事务与重试 | 根据 MySQL 的实际 DDL 行为说明，不能假定所有结构变更均可事务回滚 |
| 验证 | 变更前后结构对比、关键读写及异常场景结果 |
| 恢复 | 明确可执行的恢复步骤及数据恢复边界，保留所需备份 |

结构记录只保存必要元信息。提交前去掉环境账号、主机、DEFINER、凭据及真实用户数据；连接密码通过本机私密配置或交互输入提供。

阶段 0 不猜测生产表结构，不自动修改已有开发库，不执行清库或批量文件清理。
