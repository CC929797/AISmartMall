# AI 评测目录

阶段 0 仅建立评测材料的存放约定。目前未交付评测样本、评测运行器或效果指标，不能把本目录存在写成“已建立 AI 评测能力”。样本与基线评测按路线图步骤 17 实施，增强前后对比按步骤 25 实施。

## 后续材料约定

| 材料 | 需要记录的内容 |
|---|---|
| 数据集 | 版本、来源、授权与脱敏方式、样本数、适用任务及排除项 |
| 用例 | 稳定 caseId、输入、初始化状态、期望行为及判定依据 |
| 业务 fixture | 商品、SKU、FAQ、测试用户/订单等专用数据版本 |
| 运行配置 | 代码版本、Prompt 版本、模型和 embedding 名称、索引版本、并发及预算 |
| 原始结果 | 各 case 的实际输出、耗时、Token、检索候选、工具事件与确定性断言结果 |
| 报告 | 实际分母、成功/失败/未测数量、失败案例、适用范围及未完成部分 |

用例可采用 JSONL，但当前不生成占位样本冒充真实覆盖。多轮用例必须包含初始化上下文或有序执行前置轮次，不能把“第二款”作为无上下文单题进行评测。

## 运行边界

- 普通构建与单元测试使用 Mock，不调用真实模型，不产生真实支付或退款。
- 实际模型评测需要独立的显式入口，限制问题数、并发和费用，并保留原始结果。阶段 0 没有实现此入口。
- 测试数据和索引与日常数据隔离；不得使用真实用户资料、聊天记录、Token、API Key 或支付私钥作为样例。
- 模型输出中的用户身份、金额、库存及业务状态不能作为事实依据；相关正确性由业务数据和确定性断言核验。
- 观测不到的字段保存为 `null` 并解释原因，不填虚假零值；没有样本或分母为零时标记为不可计算。
- 构建结果、Mock 测试结果、服务联调结果与真实模型效果分别报告，不互相替代。

指标定义和实验记录格式见 `docs/智能商城项目改造路线图.md` 附录 B。每次实验先固定数据与判定规则，再比较唯一主要变更，保留失败样本，禁止虚构提升比例或线上规模。
